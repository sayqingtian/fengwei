# 峰味 · 共享菜谱本

适合 iPhone 的中文网页 App。菜谱和照片保存在服务器，手机只保留离线查看缓存。支持唯一用户名注册、账号授权审批、管理员操作日志、唯一账号 ID、Cookie 免登录、共享菜谱、独立收藏与跨设备读取、菜谱增删改、照片、搜索、分类、收藏、跟着做、历史版本恢复和 JSON 备份。

## 通过 GitHub 自动部署到 EdgeOne

在 EdgeOne 导入此 GitHub 仓库，根目录使用仓库根目录 `./`，框架选择 Other。仓库中的 `edgeone.json` 指定安装命令 `npm ci`、构建命令 `npm run build`、输出目录 `artifacts/fengwei-edgeone` 和 Node.js 22.11.0。`cloud-functions/api/[[default]].js` 是平台识别的云函数入口。

不要把输出目录设为仓库根目录或 `dist`：仓库根目录没有首页，`dist` 只有前端、不包含注册和登录接口。部署完成后先检查项目默认访问地址，再绑定自定义域名。使用 `https://www.wupanfeng.dpdns.org` 以外的入口时，在对应环境设置 `PUBLIC_ORIGIN` 为该入口的完整 HTTPS 域名，并重新部署。

GitHub 关联项目与原直接上传项目是不同项目，Blob 数据不会自动迁移。迁移菜谱时，在旧网站导出 JSON 备份后，在新网站使用管理员账号导入。详情见 [DEPLOY-EDGEONE.md](DEPLOY-EDGEONE.md)。

## 云端账号数据库

云端注册及修改密码使用独立的 Supabase PostgreSQL 数据库，通过主键约束保证用户名与密码版本记录不能被并发覆盖。菜谱、照片、收藏、权限、会话签名和原始日志继续保存在原 EdgeOne Blob；限流计数与日志查询索引复用 Supabase 账号表。

在 Supabase 新建项目，在 SQL Editor 执行 [scripts/setup-supabase.sql](scripts/setup-supabase.sql)，然后在 EdgeOne 生产环境配置 `FENGWEI_SUPABASE_URL`（项目 URL）和 `FENGWEI_SUPABASE_SECRET_KEY`（以 `sb_secret_` 开头的服务端密钥），重新部署。密钥只放在 EdgeOne 环境变量中。操作步骤见部署说明的“账号数据库初始化”。

访问 `/api/health` 返回 HTTP 200 和 `{"ok":true,"registration":true}` 表示账号数据库读写与唯一约束均通过验证。首次接入时，已有账号及密码版本在读取时迁移，账号 ID、当前密码和收藏归属保持不变。接入后删除或更换数据库配置会停止账号访问，不会回退到旧 Blob 密码。未配置过数据库时原账号仍可登录，注册提示服务尚未完成配置。本地开发仍使用原子 FileStore，无需 Supabase。

## 性能与同步

登录按用户名索引直接查找账号。常规账号验证通过一个新的 SQL 查询读取完整密码状态；首次访问旧账号时会完整迁入其 Blob 密码版本，随后不再反复查询缺失的旧记录。迁移标记存入原账号表，已有项目无需再执行 SQL。密码状态不跨请求缓存，修改或重置密码后，旧登录仍会在下次请求立即失效。

菜谱同步合并账号资料，普通大小的菜谱每页最多 100 条，页内容按 384 KiB 限制拆分。照片每组最多 8 张、最多 3 组并行读取，单组较大的照片会按 3 MiB 拆分；照片读取仍需要当前登录。重复触发的同步会合并，跨账号切换时旧同步结果会被丢弃。保存、收藏、权限申请和管理操作使用服务器已确认的结果更新当前页面，省去随后重新读取整个菜谱本或管理列表的请求；其他设备的变更可通过“同步菜谱”读取。

服务端在单次请求中复用相同的存储读取。不可变版本、照片、签名密钥及权限/收藏事件内容采用最多 8 MiB、128 项、5 分钟的内存缓存；版本和权限事件的列表仍强一致读取，密码和有效权限不跨请求缓存。已保存的操作直接使用版本中的持久化日志，避免再重复写一份日志索引。离线缓存和备份仍包含完整照片。

运行 `node scripts/benchmark-performance.mjs after` 生成 `artifacts/performance-after.json`。参考前后对照采用 70 道菜谱、12 张照片、20 个账号，模拟每次存储 15 ms、HTTP 20 ms 的相同延迟：首次同步请求从 17 次减少到 3 次，保存与收藏从 6 次减少到 1 次，重复同步从 5 次减少到 1 次。这是受控测试，线上耗时还取决于网络、函数启动及数据库所在地区。API 的 `Server-Timing` 响应头可用于区分应用处理时间和外部等待；函数地区的配置参考 [EdgeOne Cloud Functions](https://pages.edgeone.ai/document/cloud-functions)。

## 找回密码

登录页的账号与密码不预填，也不再从上次登录记录填入账号。点击“忘记密码？”填写用户名或账号 ID、线下联系方式和可选备注即可提交申请。提交不会改变密码或登录状态，页面使用统一受理提示。

管理员登录后在“我的 → 管理员工具 → 密码找回”查看申请，入口显示待处理数量；页面打开期间每 30 秒刷新。先通过已有的线下联系渠道核实账号主人身份，再设置新密码（或生成随机密码）并确认重置。成功后新密码仅在当前结果窗口显示，管理员复制后线下告知用户，关闭窗口后不再显示。用户可登录后在“我的账号 → 修改密码”设置自己的密码。身份无法核实时可拒绝申请。

重置使该账号的原密码与旧登录失效，账号 ID、收藏和权限保持不变。普通用户不能读取找回申请或操作重置；服务器、数据库和日志不保存明文新密码。找回记录沿用现有 Supabase `fengwei_account_records`，已完成数据库初始化的项目无需再建表。每个账号同一时间最多保留一个待处理申请，重复提交有 10 分钟限制；单个来源每 15 分钟最多提交 5 次；未处理申请 7 天后过期，期间密码变更会使旧申请失效。管理员自身找回需要仍有效的管理员登录，全部管理员登录丢失时需由项目维护者恢复账号。

流程中的统一受理提示、提交限流和旧登录失效参考 [OWASP 找回密码指引](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html)。

## 直接上传部署到 EdgeOne

完整操作见 [DEPLOY-EDGEONE.md](DEPLOY-EDGEONE.md)。

1. 本版支持注册，唯一用户名与密码注册后会生成账号 ID。用户名按 Unicode NFKC、首尾去空格和小写规范化，不可重复。原账号 wupanfeng 与当前密码继续可用，无需设置 RECIPE_PASSWORD。
2. 在原直接上传项目中新建生产部署，上传 artifacts/fengwei-edgeone-multiuser.zip，保留原存储与域名。
3. 用 HTTPS 正式域名登录。保存一条菜谱，在另一台设备登录并同步，确认文字和照片可读。

上传包包含完整静态页面、已编译云函数和固定版本的存储 SDK。当前平台用 cloud-functions；旧版 node-functions 的兼容包见部署说明。私人 .env、本地数据库、测试数据和备份不会被打包。

从 GitHub 克隆源码后，先运行 `npm ci` 和 `npm run build`，生成上述 ZIP，再上传到原 EdgeOne 项目。生成物在 artifacts/ 下，不提交到 Git。代码包含原账号的服务端盐与密码哈希，仓库应保持私有；不包含明文密码、注册用户数据库或个人照片。

EdgeOne 的 Blob 持久化存储是服务端的轻量文档数据库。菜谱逐条保存，照片按内容摘要复用，版本记录独立保留。数据库不放在云函数的临时文件系统里，重新部署代码不会清空同项目、同命名空间的数据。菜谱使用文档存储，账号、限流及日志查询索引使用 Supabase PostgreSQL。

## 图片空间优化

新照片在浏览器的独立 Worker 中对比 AVIF / WebP，最长边从 1280 像素开始，以 80 KiB 为目标调整画质和尺寸；难以压缩时逐步缩至 1024 / 800 像素，最终不超过 160 KiB。不会放大原图；重新编码移除 EXIF 等元数据，透明区域使用暖白底。编码器随项目部署，首次选图时按需加载约 3.3 MB 的 WASM 并缓存。上传源文件上限 20 MiB、6000 万像素；不支持解码的格式会提示失败。

图片通过二进制接口上传与读取，并在 Blob 的 `photos/<hash>.bin` 保存（首字节为格式编号，其余为原始图片字节），去掉 Base64 约三分之一的额外开销。相同内容复用；文字修改继续只提交图片引用。浏览器离线缓存和 JSON 备份仍包含完整图片。备份导入只优化实际需要新增或更新的菜谱图片。

管理员进入“我的 → 图片空间”，可查看图片占用并批量优化已有照片。处理逐张进行，可停止后继续；先写入并校验新对象，再保存旧摘要到新摘要的持久映射，最后删除旧图片对象。当前与历史菜谱的引用均通过映射读取，无需重写历史。已优化图片自动跳过，小图片不会被增大；同步时的图片版本号会更新其他设备的缓存。优化行为写入操作日志。

批量优化会降低原图画质，操作前请保存独立备份；普通 JSON 备份仅包含当前菜谱，手工复制存储时，迁移历史需保留整个 Blob 命名空间（包括 `private/photo-optimizations/`、`private/photo-optimized/` 和 `private/photo-cache-version.json`）及 Supabase 账号表。不要只复制 `photos/`。历史记录与无引用图片不会自动清理。

## 备份同步与分卷

“我的 → 菜谱备份 → 同步并生成备份”会等待已有同步结束，再重新联网读取全部菜谱分页、照片和当前账号收藏。任何一页或照片读取失败、存储异常、登录失效或账号切换，都会停止生成，不使用旧缓存冒充最新备份；普通离线浏览仍可使用缓存。生成结果显示同步完成时间，随后可逐份下载或分享。

导入与导出共用每份 **50 MiB / 10000 道菜谱** 的限制。导出按实际 UTF-8 字节数计算（含中文、转义和 JSON 结构），超限自动分卷，且不会拆开同一道菜谱。每份均为可独立导入的 v1 JSON，文件名包含同一时间、批次编号及分卷序号；请保存并导入全部分卷。空菜谱本也可生成有效备份。旧版峰味和拾味文件仍可导入；单文件导出工具若超过限制会明确报错而不会生成无法导回的文件。

普通 JSON 备份只包含当前菜谱、照片及导出账号的收藏，导入按更新时间合并。管理员可在同页生成加密的完整迁移备份，包含账号、权限、所有人的收藏、菜谱全部历史、照片及最近 7 天操作日志，并使用恢复工具迁移至新站点。完整操作见 [MIGRATION.md](MIGRATION.md)。

## 从拾味迁移

旧版 JSON 备份可以直接导入。相同网址、相同浏览器里已有本机数据时，备份页提供上传本机旧菜谱的入口。不同网址不能自动读取彼此的浏览器数据，要先导出、再导入。旧本机数据库名称保留 shiwei-private-recipes，以保护旧数据。

## 预制家常菜

presets/home-cooking-40.mjs 保存 40 道原创整理的家庭做法：家常菜 22 道、下饭菜 10 道、汤羹 8 道，均按约两人份记录。每道包含食材用量、步骤、用时与小贴士，可在菜谱本中继续编辑。

运行 `node scripts/build-presets.mjs` 生成 artifacts/峰味-40道家常菜.json。在“备份 → 选择备份文件 → 确认导入”使用现有功能即可，无需重新部署网页。预制菜谱使用固定编号，重复导入会跳过已有且较新的版本。

presets/extra-cooking-30.mjs 另收录 30 道家常菜与聚餐菜，包括糖醋排骨、剁椒鱼头、清蒸波龙、蒜蓉扇贝、姜葱炒蟹、梅菜扣肉等。多数约两人份，较大的菜按三至四人份标注。上述命令同时生成 artifacts/峰味-新增30道菜谱.json 和 artifacts/峰味-70道菜谱合集.json；所有预制菜谱默认不收藏。

scripts/seed-server.mjs 可向当前正式服务器添加这些菜谱。账号密码从隐藏的标准输入读取，不写入文件；脚本跳过已有编号和同名菜谱，写入后重新读取服务器验证。每次写入使用固定 mutationId，遇到平台请求正文读取失败时可安全重试。

新增批次使用 `node scripts/seed-server.mjs --input "artifacts/峰味-新增30道菜谱.json" --report "artifacts/extra-preset-import-verification.json"`。加 `--check-only` 只检查已有和待新增的菜谱，不写入。只添加菜谱数据时不需要重新部署 EdgeOne 代码。

## 本地开发

需要 Node.js 20 或更新版本：

```powershell
npm install
Copy-Item -LiteralPath .env.example -Destination .env
# 可选：在 .env 调整端口；账号密码已经配置
npm run dev
```

浏览器打开 http://localhost:4173。默认仅监听本机。需要局域网调试时可显式设置 RECIPE_HOST；手机的普通 HTTP 预览不支持离线安装。

本地开发使用 .data/fengwei 文件存储适配器，重启进程后保留数据；云端使用 EdgeOne Blob 适配器。目录位于公开 dist 之外，并已被 Git 忽略。

```powershell
npm run check
npm test
npm run build
```

自动浏览器检查：tests/browser-smoke.mjs 与 tests/browser-accounts.mjs，可通过 RECIPE_PLAYWRIGHT 和 RECIPE_BROWSER 指定 Playwright 与 Chromium 路径。测试使用独立演示数据与测试密码，不使用实际云端账户。

## 使用与限制

- 用 Safari 打开 HTTPS 网址，登录后添加到主屏幕。改名后原有桌面图标名称可能需要重新添加。
- 切换设备后使用同一网址和账号密码；点击同步菜谱读取服务器最新记录。目前没有自动推送。
- 离线可查看最近同步的菜谱；修改、删除、导入需要联网，保存失败时保留编辑器内容。不存在假装已上传的本地写入回退。
- 正常过期编辑会报版本冲突。真正同时保存时，双方独立版本保留并提示，通过历史版本恢复所需内容。界面展示最近 10 次版本，服务器历史目前不自动清理。
- 新照片最长边不超过 1280 像素，压缩目标 80 KiB、二进制上传上限 160 KiB；单道菜文字 JSON 限 150,000 字节；备份导入文件限 50 MiB。网络中断时导入可能部分完成，错误中会显示已保存数量，剩余可重试。
- 免费 Blob 账户额度目前为 1 GB，以控制台为准。服务器数据仍需定期独立备份。所有账号均可查看菜谱和管理自己的收藏。只有原账号 wupanfeng 是管理员；普通账号默认仅可查看共享菜谱，需要在“我的 → 账号授权”说明原因，经管理员批准后才可新增、编辑、删除、导入和恢复菜谱。管理员可撤销授权，并在“我的 → 操作日志”查看用户行为。已提供管理员处理密码找回；暂未提供修改昵称、视频或 AI 功能。
- 原账号配置与注册密码均使用加盐 scrypt 哈希；服务端签发 90 天 HttpOnly Cookie，临近到期时续期；HTTPS 下加 Secure。所有数据接口要求登录，并禁用 API 缓存。切换或退出账号时清理旧账号视图与缓存。旧版 Cookie 和原收藏会自动迁移。

## 账号权限与操作日志

导航为“菜谱本 / 收藏夹 / 我的”。账号、备份、授权及管理员日志统一放在“我的”内。

- 管理员身份绑定原 wupanfeng 账号的固定 ID，普通账号不能通过同名或传入 role/canEdit 字段提升权限。
- 新注册及已有普通账号默认只有共享菜谱查看权限，个人收藏仍独立保存。编辑申请需填写 5～500 字原因；管理员批准或拒绝时可写备注，获批后可撤销。每次接口请求读取当前权限，旧 Cookie 不会保留已撤销的编辑权。
- 用户名原子占用使用存储的 onlyIfNew 条件写入；失败时不会退回“先读后写”的防重方式。本地 FileStore 使用原子文件链接；云端账号使用 Supabase 表的 `(namespace, key)` 主键与 `ON CONFLICT DO NOTHING` 原子插入。同名并发注册只允许一个成功，其他请求读取已存在记录并返回冲突。账号数据表启用 RLS，浏览器角色没有读取权限。`/api/health` 检查数据库能力，不创建测试账号或返回私有数据。
- 原注册请求重试保持同一个账号 ID。历史重名账号保留各自 ID 和数据，新注册不能再占用这些名字；历史重名账号用 ID 登录。
- 原始日志保存在 Blob 的 private/audit/，查询索引保存在 Supabase 的 private/audit-index/，菜谱修改和授权行为还会随对应持久化记录保存操作凭据，索引写入故障不会让已保存的菜谱报保存失败。权限与申请保存在 private/permissions/、private/permission-requests/；这些数据不会作为菜谱 JSON 备份导出。只有管理员能读取账号列表和日志；日志支持搜索、结果及北京时间日期筛选，按索引每页加载 50 条；首次升级时分批整理旧日志并保存进度。
- 服务端记录注册、登录、退出、同步、收藏、菜谱新增/修改/删除/导入/恢复与授权行为，以及失败或被权限拦截的写入。查看菜谱、跟着做与导出备份由在线页面上报；离线浏览不记录。日志不会写入密码、密码哈希或 Cookie。

## 修改密码与日志导出

所有已登录账号（包括仅查看账号）均可在“我的 → 我的账号 → 修改密码”修改自己的密码。需要填写当前密码、新密码和确认新密码；新密码为 8～128 个字符。修改不改变用户名、账号 ID、角色、菜谱或收藏。

修改成功后当前设备获得新 Cookie，其他设备的旧 Cookie（含旧版 Cookie）在联网请求时失效，须使用新密码重新登录。修改后的密码不依赖源码内的初始密码配置，重新部署保留同一存储后不会重置密码。私有存储使用加盐 scrypt 和不可覆盖的密码版本链，并发修改只允许一个成功；修改请求的完整性校验同样为加盐 scrypt，不保存密码明文。密码头索引故障时可从版本链读取当前版本。用户名注册与修改密码均要求原子条件写入，能力验证失败会停止操作。

管理员在“我的 → 操作日志”可导出 CSV 或 JSON。导出包含当前已应用的搜索、结果与日期筛选条件下的记录，不限于当前显示的 50 条；每次最多 10000 条且受响应大小限制，超出时需缩小日期范围分批导出。CSV 使用 UTF-8 BOM、北京时间、标准字段转义和表格公式防护；JSON 包含导出时间、筛选条件、总条数及完整日志字段。导出仅包含日志字段，不包含密码、密码哈希、会话 Cookie 或私有存储配置。密码修改与日志导出本身也会记入操作日志。

## 并发安全与账号删除

保存、收藏与删除串行执行，过时的同步响应会等待修改完成后重新获取数据，避免页面及离线缓存退回旧版本。

云端登录、注册、找回和修改密码在尝试开始前通过 Supabase 条件更新原子占用限流次数，跨实例及重启保持限制。登录来源来自 EdgeOne Node Functions 的 `context.clientIp`，不采信客户端转发头；本地单进程开发使用同步内存计数。具体限额见部署说明。

“我的 → 账号授权”提供管理员删除账号入口，确认界面列明账号 ID。管理员自身受保护，共享菜谱和历史操作日志保留；被删除账号的旧会话失效，重新注册同名账号得到全新 ID 和查看权限。删除为保留原始记录的逻辑删除，无恢复入口；升级代码不会自动删除用户。

本次升级无需新增 SQL 表或环境变量；历史日志分批建立查询索引。索引写入失败时保留业务记录，并通过 Blob 重试队列在管理员查询时补齐。构建脚本会清理上一次构建目录，避免残留文件被重复打包。

操作日志统一仅保留最近 7 天，EdgeOne 每日定时任务和日志访问会推进物理清理，历史业务数据不删除。详见 [完整备份与日志保留策略](MIGRATION.md)。

### 3.1 可靠性与恢复

- 弱网保存保留同一次请求，自动重试并核实结果；待确认请求可在刷新后继续确认。
- 退出当前设备撤销服务端会话；支持退出所有设备。离线退出先清理本机数据，重连后补做注销。
- “我的”增加回收站与本机草稿，删除可恢复，未提交的编辑自动保存在当前账号下。
- 管理员日志页展示七天清理任务进度；EdgeOne 每日任务和 GitHub 每小时续跑共同执行。
- 应用版本更新由用户确认，有草稿时先保存再切换，不自动刷新编辑中的页面。

### 3.1.2 本机即时响应与后台同步

- 收藏、取消收藏和编辑器保存先写入 IndexedDB 账号专属任务队列，然后后台上传；不等待服务器回复。尚未发出的重复收藏点击合并为最后一次选择，已发出的请求保持原 ID 和内容，超时重试不会重复新增版本。
- “我的 → 后台同步”显示待同步、进行中和失败任务。刷新可恢复队列，断网后自动重试；关闭网页时任务暂停，下次打开并登录原账号后继续。浏览器不允许持久化时拒绝假保存并保留编辑表单。
- 编辑冲突或权限被撤销时保留本机内容，不覆盖其他设备的新版本。可重试、另存为新菜，或明确放弃失败的本机修改。还有未同步任务时暂停备份导出，避免遗漏；退出登录保留任务但清除页面中的私有数据，登录原账号后再继续。网站数据被手动清理后，本机草稿及任务无法找回。
- 有编辑权限的账号可在回收站二次确认后彻底删除菜谱及全部历史版本、收藏引用。分批删除中断后可继续；持久删除标记防止旧页面、未完成的恢复请求及旧备份导入复活同一编号。已下载备份不受影响，图片资源暂不随彻底删除清理，避免破坏其他菜谱/历史共用的图片。
- 完整迁移备份包含彻底删除标记；仅记录版本更新为 3.1.2，保留原有的安全更新流程。
